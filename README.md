## What is  DevOps
In the past, developers (programmers) and operations (server and hardware) teams worked in silos. Software was developed following the waterfall methodology, and as companies scaled, it was increasingly hard for user feedback to be incorporated continuously in the development of software, as deployments to the production environments, and releases were manual and not immediate. This, over time, has necessitated a profound shift in ideologies and working where developers and operations teams work in close collaboration. In addition, the shift from operations teams deploying software in on-premises servers to remote servers, popularly known as the cloud, has created a paradigm shift towards a developer-operations mix referred to as DevOps. It is important to note that DevOps is neither a job title nor a technology stack, but a set of processes, techniques, and ideas, whose goal is to make software delivery more efficient. To reach this goal of efficient software delivery, DevOps follows four core values: culture, automation, measurement, and sharing. While the other three are significant, automation is the most heavily focused on technical value for DevOps teams as it automates the software delivery process by managing infrastructure through code using tools such as Chef, Puppet, Docker, Kubernetes, Terraform, etc. So, what is Infrastructure as Code (IaC)?
