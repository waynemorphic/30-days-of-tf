
## DevOps

In the past, developers (programmers) and operations (server and hardware) teams worked in silos. Software was developed following the waterfall methodology, and as companies scaled, it was increasingly hard for user feedback to be incorporated continuously in the development of software, as deployments to production environments and releases were manual and not immediate. This, over time, has necessitated a profound shift in ideologies and ways of working where developers and operations teams work in close collaboration. In addition, the shift from operations teams deploying software on on-premises servers to remote servers, popularly known as the cloud, has created a paradigm shift towards a developer-operations mix referred to as DevOps. 

DevOps is neither a job title nor a technology stack, but a set of processes, techniques, and ideas whose goal is to make software delivery more efficient. To reach this goal of efficient software delivery, DevOps follows four core values: culture, automation, measurement, and sharing. While the other three are significant, automation is the most heavily focused on technical value for DevOps teams, as it automates the software delivery process by managing infrastructure through code using tools such as Chef, Puppet, Docker, Kubernetes, Terraform, etc. So, what is Infrastructure as Code (IaC)?

## IaC and the Problem it Solves

Infrastructure as Code (IaC) is the ability to provision and support computing infrastructure resources using code instead of manual processes and settings. When applications are managed at scale, manual management of infrastructure can be time-consuming and error-prone. In addition, these applications require many components such as operating systems, storage connections, network settings, etc for developers to test, stage, and deploy to production environments. IaC lets developers define their infrastructure's desired state without including all the steps to get to that state. Therefore, IaC automates the management of infrastructure through code and lets developers focus their energy on working on the business logic of their applications instead of managing environments.

There are several broad categories of IaC tools:
- Ad hoc scripts
  
Involves breaking down a manual process into discrete steps, using a general-purpose programming language such as Bash or Python to write scripts for those steps, and executing them on a server. The disadvantage of using a general-purpose programming language instead of a purpose-built IaC language is that developers can write fully custom code for every task, however they want. This tends to get messy and complicated to manage as the application scales.
  
- Provisioning tools

Tools such as Terraform, CloudFormation, OpenStack Heat, and Pulumi are responsible for creating the servers, while the other tools define the code that runs on each server. However, provisioning tools can do more than create servers. They can also create databases, caches, load balancers, queues, firewall settings, SSL certificates, routing rules, and every aspect of the computing infrastructure.

- Server templating tools

Examples include: Docker, Packer, and Vagrant. Server templating tools ideally create an image of a server, capturing a snapshot of its files, dependencies, and all relevant details. Two categories for working with images of a server are containers and virtual machines. The difference between the two is that virtual machines emulate an entire computer system, including the hardware, while containers emulate the user space of an OS, isolating it from the host machine and other containers.

- Configuration management tools

These tools install and manage software on existing servers. Examples include Ansible, Puppet, and Chef. Benefits of using these tools instead of ad hoc scripts is they allow idempotency, since it is harder to replicate the correctness of an ad hoc script after running it repeatedly, enforce coding conventions, and provide proper distribution for managing multiple servers.

## Declarative and Imperative IaC Approaches

Declarative IaC allows a developer to describe resources and settings that make up the end state of a desired system. The IaC solution then creates the system from the declared code. 

Imperative IaC allows a developer to describe all the steps required to set up the resources and get the system running in the desired state. Terraform follows the imperative IaC approach.

## Terraform

Terraform is a server provisioning tool developed by Hashicorp. It uses HCL as a programming language for developing code that provisions server infrastructure. Terraform works by using its binary to make efficient API calls to resource providers such as Azure, AWS, Google Cloud, and more under the hood. Note that while Terraform supports many different cloud providers, it is not possible to port the code between them because cloud providers don't offer the same infrastructure.

The core stages of Terraform are: write, validate, plan, and apply.

1. Write: Create the configuration file(s) to provision the resources across multiple providers, services, or on-prem.
2. Validate: Check that the code in the configuration files is error-free
3. Plan: Terraform creates an execution plan describing the infrastructure it will create, update, or destroy based on the existing infrastructure and configuration.
4. Apply: Terraform then executes the plan after an implicit approval and performs the proposed operations in the correct order, respecting any resource dependencies
